# 当前合成器 USB3 PCM 采集说明

## 原收发方式保持

CH569 使用原固件，PC 沿用参考工具的平台分支：Windows 保持 `set_configuration` → interface0/alt0 → 清除原 IN 端点 halt → 原 START 请求 → Bulk IN `0x82`；Linux 沿用已枚举配置并 claim interface0，仅未配置时 set_configuration，不 clear_halt、不 reset。Linux Qt/Tk GUI默认、显式 CLI `usb --arm-if-idle` 或 API `arm_ch569_stream=True` 先尝试读取4096字节，只有超时才调用原 `ctrl_transfer(0x40,0x8F,0x007F,0,None,timeout_ms)`；运行中的流不重复START，预取数据按原顺序保留。CLI和底层API的未指定模式仍默认只读。VID:PID=359F:3001。没有新增 Bulk OUT、启动确认、逐帧 ACK、重传或设备固件协议。

FPGA 保留参考 `EXM_HSPI.sv` 和 Gowin FIFO IP 原字节，50MHz HSPI 的转发时钟保持原反相方式。已有监视器取PCM-B在DAC截位前完整L24/R24，以L32=L24<<8、R32=R24<<8四个16位字串行写入原FIFO。未完成pair遇FIFO满会保留，只整组丢弃新输入pair，避免左右/字对齐被破坏；不新增FIFO/IP或握手。原FIFO输出寄存器初始预取修正保留，不改变HSPI native header/CRC或CH569 DMA块。

PC 可见块精确为4096字节：7帧 × (14字节头 + 512字节PCM) + 414字节零填充。头为小端 `<HBBHIHH>`：A55A、version1、flags3（已有STEREO|S32标志）、16位seq、32位rate、16位payload长度512、保留CRC字段0。每帧64组左右样本，按L32/R32小端交错；每个32位容器低8位为0，原有符号24位值用算术右移8位精确恢复。旧flags0的mono16和其它已有16/32位mono/stereo组合仍能解析；旧版上位机的mono WAV写入不能用于新版stereo，需本目录升级版。USB 分块边界不一定等于PCM帧边界，沿用流式解析；正常填充单独计数。

## 连续采集与停止条件

**可以持续传输，没有“累计传够多少MB或多少秒就自动关闭”的固件门限。** 按已核对的参考测速固件转发逻辑，发送原 START 后进入连续转发状态；电脑持续及时读取时，CH569 会不断把完整 HSPI 块交给 USB。静音时仍然传输零值 PCM，不会因为没有音符而停止。已在运行的流直接续读，不需要每个块重复发送 START。

- **4KiB 是单块大小**：一块发完就继续下一块；它不是整次采集的容量上限，也不需要先收满整个环形缓冲才上传。
- **缓冲水位控制流量**：参考固件使用16个4KiB槽，达到10槽暂停HSPI接收、降到不高于4槽恢复。这些是暂停/恢复水位，不是累计传输门限；电脑长时间不读，FPGA FIFO仍可能满并丢弃新样本。
- **上位机决定录制时长**：GUI设置 **Duration = 0** 连续采集，点击 **Stop / Finalize WAV** 才停止并完成文件；设置固定秒数则到时停止读取。参考测速程序自身的测试时长也由电脑端计时，不是固件自动关闭。
- **异常可能中断传输**：电脑停止读取、USB断连/复位、缓冲溢出或端点STALL等需要分别排查和恢复。重新连接或重新START不能保证异常期间的样本被补回；精确连续性分析应排除中断段。
- **长录音需分段**：当前双声道S32约768064B/s，标准WAV受4GiB文件格式限制，约93分钟。请在此之前Stop完成文件并另开一次采集；本工具当前不会自动滚动分段，分段间也不保证无缝。

2026-11-01，625A真实只读连续60.008秒收到 **52,715,520字节、90,090个有效帧、5,765,760组左右样本**，无效帧、跳号、重同步均为0，本次未发START，独立WAV/payload逐字节校验通过。数据全部为静音，因此这项实测仅确认该次连续传输与文件结构正常；小时级、有声内容、封包前丢样及仿真逐样本对齐仍未验收。

上述16槽、启动等待和流控细节来自已保存SHA的Sipeed参考测速源码，未读回板上CH569 Flash作二进制逐字节对照。源码分析、原始实采、失败记录和验证结果见工程根目录 `sim/results/ch569_625a_usb_recovery_20261101/report.md` 与 `continuous60_20261101T104429Z`。

## FPGA 连接

沿用已测试参考工程引脚，不占用现有41脚。新增20脚为：

| 信号 | 球脚 |
|---|---|
| HTCLK | J20 |
| HTREQ | J21 |
| HTRDY | L19 |
| HTVLD | G18 |
| HD[0:7] | G17,H22,L14,K22,K21,K18,L21,M21 |
| HD[8:15] | M22,N22,L18,M18,N19,N18,K16,L16 |

HD 为原16位三态总线，电气沿用参考 CST。实际新网表和PnR仍须验收端口、位置及电气；不能用参考板采集成功代替新码流验证。现有音频/ESP/FDC引脚与功能保持。

## 上位机

运行工具目录 `launch_pcm_capture_gui.sh`，默认USB、连续采集；Stop完成WAV。接收线程流式写盘，每声道波形只保留最近4096样本，UI更新约10Hz，不随录音时长持续占用RAM。保存文件大小仍随时长增加。当前stereo32约768064B/s，标准WAV有4GiB大小限制（约93分钟），请分段录制，正常关闭软件前先Stop。

保存的 `stats.json` 同时记录头采样率和电脑收到样本的平均速率。USB4096字节块在本采样率下约每4.67ms出现，界面显示有块缓冲/调度延迟，并非逐样本USB传输。

原序号只标识发出的PCM帧；它不能发现FPGA FIFO满时在封包前丢失的样本，也不能充当样本时间戳。当前不扩展协议，因此长时间阻塞/停止接收后，应重新启动采集并避开首段作精确对照。RMS/满量程计数只能辅助检查，无法单独证明沙哑原因或排除内部24位回绕。抓包起点没有FPGA样本级触发时间，后续仿真与实测比较需对齐内容/延迟后逐样本分析。

## 验证边界

本轮验证包括实际EXM_HSPI、未改Gowin生成FIFO和官方四态原语模型；4096B块、原版/新版解析器逐字节相同；24位正负极值/低8位非零/左右独立/满FIFO整pair丢弃与恢复；真实音频模块完整24位tap对全精度golden、DAC高16对独立串行解码；截低8位/错左右负对照均失败；Qt/Tk在96008Hz stereo32假源下真实工作线程、双波形和Stop/WAV测试。Fake界面数据与RTL数据均明确标记，不声称来自USB实板。

新FPGA正式综合/PnR验收和实板采集以sim/results/ch569_realtime_pcm_20261101/continuation.json权威入口及当前iteration_results的报告为准；本轮完整精度结果在sim/results/ch569_stereo24_20261101。verify_capture.py现按实际声道/位宽检查，并流式逐字节比较WAV和payload.pcm，故意损坏WAV负对照已通过。FIFO跨域只对实际Gray指针第一同步级使用有界20ns max_delay及hold例外；其余路径保留分析。原参考没有可用的板外HSPI时延预算，外部setup/hold及线缆/CH569实际波形仍需实测，不用虚构数字填充。

原始参考 `/media/ice/D;/FPGA_tools/CH569_PCM_cd03bd0` 与 `/media/ice/D;/FPGA_tools/ch569_pcm_capture` 保持只读。本工具没有自动更新CH569固件或烧录设备的功能。
