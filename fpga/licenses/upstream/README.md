## 修正与幅度约定

相位的高 2 位决定象限，其后 8 位决定 ROM 地址；低 14 位是格内位置。ROM 基点在每格中心，因此余量为：

```
r = unsigned(phase[13:0]) - 8192         // -8192 .. +8191
epsilon = 2*pi*r / 2^24
y ≈ S(theta0) + C(theta0)*epsilon
```

`RADIAN_FACTOR=floor(2*pi*2^14)=102943`。15 位有符号余量与 18 位有符号常数产生完整 33 位乘积，缩放为 19 位有符号相位偏移，再与 24 位余弦相乘，保留完整 43 位乘积。基幅度左移 24 位后与修正项在 **49 位有符号加法器**中相加，包括一个额外整数保护位。

修正先加到高精度基幅度，再统一除以 `2^(24+8)`，转换为原 Q2.16 数值码。保持原算术右移／向下量化策略；单个输出码代表 `2^-16`。正弦输出钳位到原名义范围 `-32768..32767`，防止一阶近似在峰值附近越界。PWM 的较大瞬时幅度仍通过原 25 位计算及 18 位输出保留，不使用正弦钳位器。

本版本固定为当前工程的 24 位相位、256 点半格 ROM、18 位输出；没有开放未验证的任意参数组合、上传波表或可切换修正算法。`LUT_FILE` 必须指向相同约定的 256×24 位半格正弦表。

## 预计算斜率表生成（256点结果已供新 RTL 使用）

生成器只使用 Python 标准库，命令行接口为 `--points`、`--width`、`--fraction-bits` 和 `--out-dir`；也可调用纯计算函数 `calculate_tables(points=256, width=18, fraction_bits=15)`。`--points` 表示**四分之一周期**的半格采样点数，默认 256，对应完整周期 1024 个粗格点。点数须为正的 2 次幂，并在固定 24 位相位下留下至少一位格内余量；点数上限为 2,097,152。系数位宽支持 2..32 位；不能容纳系数、负小数位或小数位不小于总位宽的配置会在创建输出前拒绝。

本次已实际运行：

```bash
python3 -B src/DDS/DDS_improve/tools/generate_slope_lut.py \
  --points 256 --width 18 --fraction-bits 15
```

默认生成目录为 `rom/precomputed_256x18q15/`。改变点数的示例：

```bash
python3 -B src/DDS/DDS_improve/tools/generate_slope_lut.py \
  --points 512 --width 18 --fraction-bits 15 --out-dir /tmp/dds-slope-512
```

输出目录必须是新目录；已有目录会被拒绝，避免覆盖之前的结果。未指定目录时，名称由点数、位宽和小数位生成。四份交付文件为：

- `sine_midpoint_<N>x24.hex`：配套正弦基值。256 点结果与上方既有 ROM 逐字节一致；改变点数时也生成对应基值，避免不同采样网格混用。
- `slope_midpoint_<N>x<W>q<F>.hex`：一行一个定点系数，纯十六进制，可供 `$readmemh` 使用；默认每行 5 个 hex 字符，有效位宽 18 位。
- `coefficients.csv`：格点编号、24 位相位中心、角度、基值、余弦码、未量化斜率、定点系数与 hex，便于检查。
- `coefficients.json`：参数、计算公式、象限符号规则、消费缩放、逻辑存储量、独立误差上界和文件 SHA-256。

沿用原工程峰值 `A = 2^23-1` 和最近值／平局取偶数舍入。这里预计算的是**每一个 24 位相位码对应的幅度斜率**，不是每一个 ROM 地址的斜率：

```text
theta[i] = pi/2 * (i+0.5)/N
S[i]     = round(A * sin(theta[i]))
C[i]     = S[N-1-i]                         // 同一半格表的余弦幅度码
B[i]     = round(C[i] * (2*pi/2^24) * 2^F)  // 弧度换算已包含在斜率中
```

默认 `W=18, F=15` 为有符号 Q3.15（整数位包括符号位）；最大系数约为 pi，码值范围为 316..102943。表内只存第一象限的正值。四个象限使用与正弦相同的镜像地址，斜率的符号由 `quadrant[1] XOR quadrant[0]` 决定；不需要额外的四份表。

未来消费时，格内余量仍为有符号的 `r = unsigned(phase_remainder) - 2^(remainder_bits-1)`，用宽位整数计算 `((signed_S << F) + signed_B*r) >>> (F+8)`，然后钳位到原正弦名义范围 −32768..32767，输出 18 位 Q2.16。默认 `r` 为 15 位有符号量，乘积需要 33 位，基值与乘积相加应保留保护位，例如 40 位有符号加法；不能将 Q3.15 系数当作原 Q2.16 音频直接使用。

默认基值为 256×24=6144 bit（768 byte），斜率为 256×18=4608 bit（576 byte），合计 10752 bit（1344 byte，1.3125 KiB）。这是有效数据位数，HEX 文本大小和实际 FPGA 存储块分配另计。原dds_improve_taylor_sine作为历史参考保留；新dds_improve_slope_sine使用256点预计算表。生成其它点数不会自动改变固定256点的生产RTL。
