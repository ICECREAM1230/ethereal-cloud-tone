# AE350 Tcl/GUI 同步修复（2026-10-29）

目标：两个AE350工程使用同一项目目录生成配置和报告；GUI关闭时才允许CLI写该项目。复用已验证的字段级配置保存器，在原生CLI完全退出后补丁式恢复配置，保留未知字段与排版。每次syn/pnr保存输入和产物身份，验证新报告与原生ResultFileList属于同一工程和输出名前缀，不将失败或过期结果当成新结果。报告不同目录时给出真实工程路径，不自动覆盖其他版本的impl。GUI重新打开项目后读取同一目录；不热改运行中GUI。

选择：在本工程复制现有两个小同步组件并扩展结果验证，保证复制工程后仍自足；不依赖原合成器目录，不修改全局gw_sh或厂商库。修改脚本均保留前像于provenance/gui_sync_*。

实施顺序：
1. 添加失败用例：报告新鲜度、源码漂移、结果路径错配、成功manifest及配置字段保留。
2. 添加工程本地配置保存器、结果验证器，两个Tcl入口接入并增加config模式；manager输入快照包括这些组件。
3. 跑单元测试及隔离小工程官方config/syn/pnr，验证关闭重开配置一致、HTML框架与原生报告同属本轮。
4. 在正式AE350执行config，核验GPRJ/输入/既有报告不变。验证后自动后台启动控制工程综合与独立日志终端，10分钟安排一次检查，通过且输入一致才启动PnR并结束该检查轮。

不改RTL、CST/SDC、固件、时序目标，不写设备。没有暂存或提交授权。真实AE350时序是否通过取决于后续官方实现，当前已知时序违例不会被本修复消除。

审查修正：PnR必须使用本轮可验证的综合凭据与实际.vg，开始/完成/后续检查均核验；GUI最终配置需与构建设置相同。初始化输入覆盖无扩展名itcm0–itcm3及IPC，防止源码未变而固件镜像改变时误用旧结果。
