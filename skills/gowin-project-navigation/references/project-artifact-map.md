# Gowin project artifact map

This map is intentionally generic. A project may omit stages, use custom directories, or place files outside `src/` and `impl/`; confirm with the `.gprj` and `.gprj.user` files.

## Project root

| Pattern | Typical role | Authority |
|---|---|---|
| `<name>.gprj` | Gowin FPGA project XML; device and `FileList` | Primary project definition |
| `<name>.gprj.user` | GUI/process state and `ResultFileList` | Generated/user-session metadata |
| `src/` | RTL, HDL headers, constraints, IP files and debug configs | User design inputs, if referenced |
| `impl/` | Generated synthesis and implementation work area | Tool outputs |
| `*.fs` | Gowin programming/bitstream image in observed projects | Generated; confirm exact programming flow |

## Common input extensions

| Extension | Meaning | Typical stage |
|---|---|---|
| `.v`, `.sv`, `.vh`, `.svh`, `.vhd`, `.vhdl` | RTL/HDL and headers | Synthesis/simulation |
| `.cst` | Physical constraints: I/O, primitive, group, clock-net and related constraints | PnR |
| `.sdc` | Timing constraints: clocks, I/O delays, exceptions and reports | STA/PnR |
| `.gsc` | GowinSynthesis constraint file, commonly containing synthesis attributes | Synthesis |
| `.vp` | Encrypted Verilog HDL/project pack file; may be generated by project encryption or supplied by an IP | Synthesis/IP integration |
| `.vhdp` | Encrypted VHDL project file | Synthesis/IP integration |
| `.vgp` | Encrypted Verilog gate-level/project file | Synthesis/IP integration |
| `.ipc` | Gowin IP configuration/project descriptor | IP generation/project input |
| `.mod` | IP/module metadata or generated module support file | IP generation/simulation |
| `.gao` | GAO configuration for post-synthesis netlist capture | On-chip debug |
| `.rao` | GAO configuration for RTL-level capture | On-chip debug |
| `.coe`, `.hex`, `.dat`, `.bin` | Memory/flash initialization or related data; exact use is context-dependent | IP/bitstream/debug |

## Process and simulation files

| Pattern | Meaning | Caveat |
|---|---|---|
| `impl/process_config.json`, `impl/*_process_config.json` | Generated implementation/bitstream process settings | Supplementary saved tool options; not the project manifest or a complete statement of design intent; may contain case-variant keys |
| `sim/`, `simulation/` | Common simulation work directories | Some projects use simulator-specific or custom names |
| `.wlf` | Questa/ModelSim waveform database observed in the repository | Simulator output, not a Gowin implementation result |
| `.vcd`, `.prn`, `.mti`, `.mpf` | Common waveform, export, or simulator project artifacts | Interpret from the simulator and project context |

## Generated synthesis area

`impl/gwsynthesis/` commonly contains:

- `<name>.prj`: generated GowinSynthesis project input, including device, file list and synthesis options;
- `<name>.vg`: post-synthesis gate-level netlist when generated;
- `<name>_syn.rpt.html` or similar: synthesis messages/details;
- `<name>_syn_rsc.xml` or similar: synthesis resource summary;
- temporary parser/configuration files.

The `.prj` is useful for reconstructing what the synthesis process consumed, but it is generated and may contain absolute paths from the machine that ran the build.

## Generated PnR area

`impl/pnr/` commonly contains:

- `<name>.rpt.html` or `<name>.rpt.txt`: place-and-route report;
- `<name>.tr.html` and `<name>.timing_paths`: timing summaries/path data;
- `<name>.power.html`: power analysis result when enabled;
- `<name>.pin.html`: pin report;
- `<name>.fs`, `<name>.bin`, `<name>.db`, `<name>.binx`: implementation/programming/database outputs;
- `cmd.do`, `device.cfg`, logs, temporary and tool database files.

The exact set depends on enabled processes and software version. Use `.gprj.user` `ResultFileList` to find the files the GUI registered as results.

## IP-generated subtrees

An IP core may create a directory below `src/` containing an `.ipc`, generated HDL (`.v`/`.vhd`), simulation models (`.vo`/`.vho`), a temporary directory, and metadata. A generated file is part of the build only when it is enabled/referenced by the `.gprj` `FileList` or by a generated synthesis project.

Some IP outputs observed locally include `.prj` and `.vg` below `src/**/temp/**`. These are IP-level generated projects/netlists and must not be mistaken for `impl/gwsynthesis/<top>.prj` or the top-level post-synthesis netlist.

## Evidence checklist

When reporting a path, capture these facts:

1. Is the file listed in `.gprj`?
2. Is it listed in `.gprj.user` as a result?
3. Does it exist on disk now?
4. Is it an input, an intermediate, a report, or a programming artifact?
5. Does the path contain machine-specific absolute paths?
6. If it is an input, is its `enable` flag set to `1` in `.gprj`?


## Encrypted source handling

Gowin Software can encrypt HDL project files. The local SUG100 describes default output under an `encrypted_sources` directory and appending `p` to the original extension, for example `.v` → `.vp`, `.vhd` → `.vhdp`, and `.vg` → `.vgp`. SUG1220 documents the Tcl `encrypt` command and its `top.v` → `top.vp` example. Never assume that every protected file is an IP core.

When a `.vp`, `.vhdp`, or `.vgp` file appears:

1. Identify whether it is listed in the `.gprj` `FileList`, an IP-level `.prj`, or a wrapper comment such as `file0/file1`.
2. Report its path, extension, enable state, and whether it exists.
3. Explain that Gowin tools consume the protected file while its implementation is intentionally opaque.
4. Use the surrounding wrapper, module name, ports, parameters, and project configuration for integration-level reasoning.
5. Do not print, decode, decompile, or speculate about the protected body. Do not replace it with guessed RTL unless the user explicitly requests a separate design task.
