## 五端统一生成

schema现在规定FLAGS掩码 READY=1、SELECTED=2、MUTED=4、BUSY=8、FAULT=16；
不能把“已安装且ready”和“已选中”合为一个状态。后端已准备但未选中时PHASE=READY，
上位机可据实际能力选择FM，音频仍按当前模式输出。

FEATURES的bit0..9依次为NOTE_ON、NOTE_OFF、SET_PITCH、SET_GAIN_PAN、SET_PARAMETER、
APPLY_PRESET、RELEASE_ALL、PRIORITY_PANIC、NEXT_NOTE_PARAMETERS、NATIVE_STEREO_PAN。
仅公布实际实现和验证过的功能，保留位为0。代码引用生成常量，不能在各端手抄掩码。

生成器另从profile派生五端静态VOICE_COUNT、PATCH_OPERATOR_COUNT、MAX_OPERATOR_COUNT
常量，例如`FM_PROFILE_JT51_OPM_VOICE_COUNT`。用于HDL elaboration和C存储容量，解决
部分仿真器不能在常量表达式中读取packed struct member的限制。它们和运行时描述来源
相同。MAX不能代替所选声部的实际算子数；异构后端仍逐声部验证。
控制桥容量参数默认使用生成的8，未来容量16/实际profile8测试不把不存在的声部变可用。
修改profile可生成新的静态容量，无需改变命令word布局。

## 复位与切换的联调约定

独立Panic可取消初始化。SELECT在桥观察到成功完成之前被取消时，恢复之前的selected/bound；
同拍已经观察到成功done则该绑定完成优先，随后Panic静音。session/epoch不回滚。
后端使用独立停止的稳定载荷跨过native完成到synth观察done的窗口，恢复相同绑定和patch。

Panic保留当前patch参数，复位芯片后重新装载；显式SELECT/APPLY_PRESET更换默认/指定patch。
原生PLL失锁使FM控制与后端共同复位、session清0；最终PCM静音锁存持续到显式新SELECT
成功，避免自动回退DDS。主PCM帧、重采样窗口与output_tilt旧状态同时清理。
上位机遇到session复位必须重新读能力、建立nonce、清旧按键/租约；不得自动重播旧客户端意图。


## profile 与 backend 编号的分离

`profile.id` 是目录查询键；`profile.backend_id` 是SELECT与capability中的wire音源编号；`profile_version` 区分该音源不同能力版本。客户端先按backend/version和全catalog摘要匹配，再以profile.id查询参数、preset及算子。生成器已拒绝重复backend/version组合，不应让调用方假定两个编号相同。

控制桥原版因当前JT51两个编号都为1而未暴露混用。已保留旧RTL、修改CSR/SELECT/selected条件为profile_info.backend_id，并实际用生成的profile99/backend1验收433项；canonical profile1的三路423项控制回归仍通过。该修复不改变12-word格式、ABI、端口或canonical生成物。证据：`/home/ice/Project/synth-jt51-stage2-20261011/control-bridge/profile-id-boundary/result.json`。

这证明控制目录查找和wire选择分离，不证明JT51 adapter可随意变成别的芯片：原生8×4、特性掩码、采样率和音高边界仍由真实adapter验证。多个JT51实例或另一FM算法均需相应实现、资源／期限及音频验收。
