# FM ABI 1.1 接口生成器

2026-10-11。当前 `schema_version=1.0.0`，状态为 `contract_frozen_not_integrated`。接口冻结与硬件集成是两个验收点；生成物定义常量、12-word codec 和目录元数据，不能证明正式 SPI、HTTP、mailbox、CDC、adapter 或设备已支持 FM。`spi.implemented_in_active_project=false`；HTTP 仍为 `proposal_not_frozen`。

## 输入与复现

生成器只使用 Python 标准库。`schema/fm-control.schema.json` 定义 ABI、target、scope、命令顺序、word 地址、枚举与解析预算；`schema/backend-profiles.json` 定义后端拓扑、参数范围、单位、生效时机与预置。旧 `backend-reference-profiles.json` 不参与生成。

```sh
python3 tools/gen_fm_contract.py
python3 tools/gen_fm_contract.py --check
python3 tools/gen_fm_contract.py --schema schema/fm-control.schema.json --profiles schema/backend-profiles.json --out /tmp/fm-generated
python3 tools/gen_fm_contract.py --schema schema/fm-control.schema.json --profiles schema/backend-profiles.json --out /tmp/fm-generated --check
```

默认路径相对于生成器所在接口根目录；显式相对路径相对于当前目录。`--check` 只读取并比较 schema 列出的五个生成物，不创建或修改文件。缺失/内容漂移退出1，输入或读取错误退出2，匹配退出0。正常生成只覆盖预期路径，不删除其他文件。

输出包含完整 schema 版本与三种 identity：

- `FM_SCHEMA_SHA256 = SHA256(schema 原始字节)`。
- `FM_PROFILES_SHA256 = SHA256(backend-profiles 原始字节)`。
- `FM_CONTRACT_SHA256 = SHA256(b"FM_CONTROL_IDENTITY_V1\0" + schema_digest_bytes + profiles_digest_bytes)`；两个 digest 各32字节，使用二进制 digest，不是64字符 hex文本。组合 identity 仅供构建追溯。

原始文件空白/换行也参与摘要。生成无时间戳；相同输入字节与生成器产生相同输出字节。变更任一输入后须重新生成、运行 `--check`，请勿手改生成物。

能力 `PROFILE_SHA256_0..7` 比对整个 catalog 的 `FM_PROFILES_SHA256`，将 digest 字节0..3、4..7……28..31分别解释为 big-endian uint32 word0..7，且必须与 `BACKEND_ID`、`PROFILE_VERSION` 配对。查询对象的 `profile_sha256` 同样是 catalog 摘要，不是单独 profile JSON 摘要。ABI 必须精确匹配1.1；`abi_compatible` 等 helper 只做编码比较，运行时启用仍须真实 capability。

## 输出与命名

| 文件 | 入口 |
| --- | --- |
| `generated/c/fm_contract.h` | header-only C/C++ helpers、const catalog |
| `generated/sv/fm_contract_pkg.sv` | packed command/metadata、整数 case/functions |
| `generated/js/fm-contract.mjs` | ES module，catalog 深层冻结 |
| `generated/java/cn/fpgasynth/control/generated/FmContract.java` | `FmContract` 静态 helpers、不可变对象 |
| `generated/python/fm_contract.py` | uint32 helpers；查询返回目录副本 |

所有端使用 `FM_<constant>`、`FM_<enum组大写>_<成员>`、`FM_REG_<寄存器>`，如 `FM_SCOPE_PATCH_OPERATOR`、`FM_UNIT_CHIP_CODE`、`FM_APPLY_TIME_NEXT_NOTE`。`FM_REG_*` 是完整 word address，已包含 `SPI_WORD_BASE=0x0600`，不能再次加 base 或误作 byte address。

`FM_COMMAND_WORD_COUNT=12`、`FM_COMMAND_BYTE_COUNT=48`、`FM_CMD_WORD_<字段大写>` 与字段寄存器来自同一 schema。codec 只校验精确结构、长度与 uint32，不代替 opcode、身份生命周期或 mailbox 状态机。

## 命令 codec

冻结顺序为 `opcode_id, scope_id, target_word, parameter_id, value_u32, arg0_u32, arg1_u32, session_id, engine_epoch, topology_generation, voice_generation, sequence_id`，寄存器为0x0610..0x061b。`CMD_COMMIT=0x061c` 最后写，运输层须验证其值等于非零 sequence_id。codec 允许 transport 字段为零，以表达boot/SELECT场景，不据语法检查宣称命令可执行。

| 语言 | 序列化 / 反序列化 |
| --- | --- |
| Python | `serialize_command(dict) -> tuple` / `deserialize_command(list或tuple) -> dict` |
| JS | `serializeCommand(object) -> Array` / `deserializeCommand(Array) -> object` |
| C | `fm_serialize_command(const fm_command_t*, uint32_t*, size_t) -> bool` / `fm_deserialize_command(const uint32_t*, size_t, fm_command_t*) -> bool` |
| Java | `serializeCommand(Command) -> long[]` / `deserializeCommand(long[]) -> Command` |
| SV | `fm_serialize_command(fm_command_t) -> fm_command_words_t` / `fm_deserialize_command(fm_command_words_t) -> fm_command_t` |

Python/JS 拒绝缺失或多余字段、bool、小数、空值、负数、溢出。Python 抛 ValueError，JS 抛 RangeError，Java constructor/反序列化抛 IllegalArgumentException。Java 使用long保存unsigned32；C 校验精确count和非空指针，失败不写输出，逐字段赋值，不依赖struct大小、padding或memcpy。C/Java/SV的typed输入无法恢复调用前已发生的截断，调用方须在narrow前校验原始范围。

SV struct首字段opcode_id在packed384最高32位；`fm_command_words_t` 是 `logic [11:0][31:0]`，words[0]是opcode，所以flat bit order与struct相反。必须显式调用codec，不能直接cast替代。字段使用sequence_id、parameter_id、operator_index等完整标识符。宽度已固定，仿真前可调用fm_command_valid/fm_command_words_valid检查X/Z；宽输入转换前应校验范围。

Panic有独立PANIC_RESULT_SEQUENCE/RESULT/SESSION/EPOCH和最后请求缓存，不能覆盖普通RESULT；codec不实现其接受、完成、取消或重试状态机。

VOICE_QUERY_INDEX 由唯一设备写入 owner 串行查询：写后先确认读回的是 sysclk 已应用且等于请求的 voice，再读 generation/operator count，最后验证 status_generation 首尾相同。旧索引不能仅凭 generation 未变就误判查询完成。

## target 与目录

target高16位是voice、低16位是logical operator index，NONE为0xffff。打包允许两字段0..65535（含NONE），解包提取unsigned16。可打包不等于有效scope目标。

validator参数统一为 `(scope, word, voice_count, selected_operator_count, patch_operator_count)`。预算voice为1..256，两个operator count为0..32；任何输入不合法、计数超预算或未知scope均false。VOICE_OPERATOR用被选声部的实际count，PATCH_OPERATOR用独立patch count。

| Scope | voice | operator |
| --- | --- | --- |
| ENGINE / PATCH | NONE | NONE |
| VOICE | < voice_count | NONE |
| VOICE_OPERATOR | < voice_count | < selected_operator_count |
| PATCH_OPERATOR | NONE | < patch_operator_count |

五端原target APIs保留。Python unpack返回(voice,operator)，JS返回对象。C打包传入uint32_t* out并返回bool；SV使用16-bit输入，从32-bit输入转换前必须调用fm_fields_valid。

目录查询：

- Python get_profile/get_parameter/get_preset；JS与Java getProfile/getParameter/getPreset，未知ID返回None/null。
- C fm_profile/fm_parameter/fm_preset返回const pointer，未知ID返回NULL。
- SV fm_profile_info/fm_parameter_info/fm_preset_info返回packed numeric struct，用valid区分未知ID。标签只保留在软件端。
- 五端profile_native_register_slot/profileNativeRegisterSlot/fm_profile_native_register_slot与对应key_on_bit查询仅返回profile mapping，不拼接芯片地址；非法uint32、未知profile/operator或缺mapping统一返回0xffffffff。
- 每端profile_operator_count/profileOperatorCount/fm_profile_operator_count按实际voice查询。Python/JS未知为None/null，Java为-1，C通过bool与out返回，SV为0xffffffff。
- 每端validate_parameter/validateParameter/fm_validate_parameter(profile_id,parameter_id,scope,word,value)选择profile的参数范围与实际拓扑，再调用通用target validator。
- 预置values列表包含parameter_id/operator_index/value_u32；PATCH的operator为NONE。C preset有values/values_count，Java Preset.value(index)，SV fm_preset_value_info(profile_id,preset_id,value_index)。

参数元数据有id/name/minimum/maximum/scope_id/unit_id/apply_time_id/value_type_id；profile有id/backend_id/profile_version/voice_count/patch_operator_count/runtime_available/parameter_count/preset_count和每声部count。SHA words：Python/JS FM_PROFILES_SHA256_WORDS；C fm_profiles_sha256_words[8]；Java profilesSha256Word(index)；SV fm_profiles_sha256_word(index)。

JT51 profile1是实际8×4，逻辑顺序[M1,C1,M2,C2]，adapter register slots=[0,2,1,3]、KeyOn bits=[3,4,5,6]。预置由native测试M1/M2/C1/C2数组显式重排为逻辑顺序。13个参数均为chip_code、next_note，不能标注为毫秒/dB；不承诺全MIDI音区声学误差。MSFA profile2是8×2离线参考，两者runtime_available均false。

未来16×6或异构声部可通过新增合法profile表达，通用target/command codec无需修改。每声部count、patchcount、labels、adapter mapping、参数与预置必须一致；metadata预算不承诺仅改声部数就能扩容JT51单实例硬件。

## 验证边界与历史

```sh
PYTHONDONTWRITEBYTECODE=1 python3 tools/test_gen_fm_contract.py
python3 tools/gen_fm_contract.py --check
```

自身测试覆盖非法field/type、register/enum/profile/parameter/preset冲突与越界、资源预算、复现与只读检查。跨语言owner以本阶段固定fixtures/runner独立检查往返、非法包、目录范围与扩展实例；旧草案测试不能代替ABI1.1验收。

SV所有$isunknown(nonconstant)语句同时有ifndef SYNTHESIS与Gowin官方 `/*synthesis translate_off*/`/translate_on保护，因为本机Gowin不自动定义SYNTHESIS。综合保留整数范围、case、scope、目录检查；仿真未知保护不替代物理CDC、复位或合法性机制。fm_command_valid在综合中只能确认typed width，不能替代生命周期状态机。Gowin/package探针、post-synthesis、正式工程STA、PCM与实体板须分别验收。

旧schema0.1.0/ABI1.0保留在schema/history/fm-control-0.1.0.schema.json，只有常量/target helper且未接入。本版不承诺其命令寄存器兼容；旧backend-reference-profiles.json仅保留来源历史。
