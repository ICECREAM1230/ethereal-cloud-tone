# 本地串口 MIDI 调试工具设计

日期：2026-10-25。范围是电脑端脚本和供 AI 读取的 Skill；不改 ESP32/FPGA 固件，不操作真实硬件。

链路：电脑 → USB 串口 → ESP32 固件命令处理 → 现有 SPI → FPGA。
目前未确认 ESP32 的串口命令协议，因此示例 `midi {hex}` 只是占位格式。

实现步骤：

1. 先编写行为测试：MIDI 编码、参数拒绝、无副作用预览、未确认协议保护、PTY 串口收发与超时。
2. 实现 Python CLI，提供 ports / encode / send / midi / note / listen。标准输出为一个 JSON 对象，错误用非零退出码。
3. 串口连接要求显式端口和波特率；写入要求 --execute。使用端口锁和有限读写时间，不自动重试命令。
4. 每次真实连接保存 events.jsonl、rx.bin、tx.bin、result.json。发送前收到的内容单独标记，不参与响应匹配。
5. note 在同一次连接中尝试 Note On 和 Note Off，异常时也尝试释放；无法保证断线后的释放成功，结果必须报告。
6. 编写 Skill、用户说明和未确认的协议示例，运行 PTY 测试和 Skill/包结构校验后生成 ZIP。

验收：预览不打开任何端口；协议未确认时 MIDI 写入被拒绝；真实 PTY 能收到准确字节；旧数据不能充当新响应；超时明确报告；原始接收数据无损保存；按键测试自动发 Note Off；没有真实设备写入。

限制：本工具不实现 USB MIDI 设备枚举，也不补充 ESP32 固件命令处理器。串口响应、ESP32→SPI、FPGA 解码、声音输出是不同层次的证据，不能相互替代。
